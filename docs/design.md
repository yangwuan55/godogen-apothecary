# 策划设计说明（docs/design.md）

> 交接任务：《炼金药铺》从"键盘驱动的原型"完善为"陌生人打开就会玩"的完整 2D 模拟经营。
> 本文件是本次改造的设计依据。设计准绳：**玩家体验与可玩性第一**。

## 1. 问题定位（现状审计的根源）

当前版本核心循环（进货→接单→炼药→出货→赚钱→解锁）已经成立，但**交互通道、反馈密度、视觉层级**三项严重不足：

| 病症 | 根源 | 后果 |
|------|------|------|
| 无鼠标 | 全键盘数字键 | 陌生玩家"点击没反应"，功能感知为不可用 |
| 顾客气泡空 | `Text2d::new("")` 无系统更新 | 顾客不说话，订单信息全靠右侧面板 |
| 面板=纯文本 | 单行文本堆叠 | 无按钮/价格高亮/禁用态/悬停，像调试输出 |
| 无音效/无暂停/无引导 | 未实现 | 反馈单一、节奏无法控制、新手茫然 |
| 炼药反馈弱 | 两行色条 | 温度区间看不见、烧焦无预警、搅拌时机靠猜 |

**结论**：这不是"加几个功能"的问题，而是要把游戏从"可读"提升到"可玩"。

## 2. 核心循环改造

保持既有循环不变（它是对的），把每一环的**反馈密度**补足：

```
进货 ──► 接单 ──► 炼药 ──► 出货 ──► 赚钱/声望 ──► 解锁
 │         │         │         │         │
买按钮/批量 顾客气泡  温度窗口    品质动画   金币飘字   更好顾客
数量+-     等待/离开  烧焦预警   金币进账    声望升级  新配方/新升级
```

## 3. 输入信息架构（统一输入通道）

**原则**：鼠标与键盘是完全对等的输入通道，任何关键操作两者皆可。

- 新增 `UiAction` 消息：开始游戏 / 接单 / 搅拌 / 升温 / 降温 / 数量+/− / 买材料 / 买升级 / 切面板 / 暂停 / 继续 / 结算 / 重开。
- 键盘系统与鼠标系统都只负责把输入**翻译成 `UiAction`**；各业务系统（顾客/炼药/经济/面板）统一消费该消息。杜绝"两种输入两套逻辑"。

```
鼠标点击按钮 ─┐
键盘按键    ─┴─► UiAction 消息 ──► 各业务系统消费
```

## 4. UI 视觉系统（UI Kit）

统一调色板与组件规范，替换全部"裸文本"：

- **配色**：深蓝底 #12101E、面板 #191726、卡片 #221F33、边框 #3A3552；
  强调色：金 #F9C74F（金币/成功）、绿 #6BCB77（进度/可用）、红 #E05A5A（危险/烧焦）、蓝 #6FA8DC（信息）。
- **组件**：圆角按钮（hover 提亮 / press 压暗 / disabled 置灰）、彩色徽章图标、卡片、进度条（含理想区间色带）。
- **字体层级**：标题 30/24 粗体、正文 16、说明 14、提示 13。
- **图标**：用"色块徽章 + 单字"（金/声/日/收/时）代替 emoji（Noto Sans SC 无彩色 emoji，规避豆腐块）。

## 5. 新手引导（不打断节奏）

7 步提示式引导，全部**只提示、不拦截**，由游戏事件自动推进：

1. 顾客来了 → 点「接单」
2. 接下订单 → ↑↓ 把温度调进金色区间
3. 熬制中 → 进度条到搅拌点按 Space/点「搅拌」
4. 出货成功 → 金币声望到账
5. 材料不够 → 打开「市场」
6. 市场 → 点原料行购买，+/− 调数量
7. 攒够金币 → 升级工坊

目标物高亮（脉冲描边）+ 底部引导横幅。capture 模式可关（`TutorialSettings.enabled=false`）。

## 6. 炼药反馈强化

- 温度条上加**理想区间色带**与刻度（0/25/50/75/100）+ 实时数值。
- **烧焦预警**：温度超过区间 +8° 进入预警区，温度条闪橙红、文字"小心烧焦！"脉冲。
- **搅拌时机提示**：进度进入搅拌窗口时"现在搅拌！"高亮。
- 坩埚液面颜色随温度变化（冷=蓝 / 区间=配方色 / 过热=橙红），已有气泡粒子持续。

## 7. 顾客表现（气泡 + 动画）

- 气泡内容按状态机更新：等待=「想要『治愈药水』」、接单后=「在熬了…」、低耐心=红字「快一点！」，离开=「等不及了…」。
- 等待时轻微浮动；接单时开心跳一下；出货时向柜台方向飘金币/品质字。
- 低耐心时气泡变红 + 红色感叹号，形成"再不处理他要走了"的紧迫感。

## 8. 暂停

`Esc` 或 `P` 或 HUD 暂停按钮 → 弹出暂停菜单（继续 / 回标题 / 退出游戏）。暂停时冻结：日钟、耐心、炼药进度、世界动画；UI 与输入照常（否则无法点"继续"）。

## 9. 结算 / 胜负画面

- 日结算：今日收入、租金、净收入、服务/流失、完美次数、声望进度 + **当日品质分布条形图**（劣/普/良/完 4 条）+ **明日目标**（如"声望升到 Lv3"）+「继续营业」「回标题」按钮。
- 破产 / 胜利：统计（坚持天数、服务/流失、声望）+ 一键重开按钮。

## 10. 音效与 BGM（程序合成）

无外部音频资源（skill 已验证无付费 API）。全部**运行时程序生成 16-bit PCM WAV**，写入内存 `AudioSource`，来源已在代码注释与 README 注明：

- SFX：点击（短促方波）、搅拌（咕噜）、出货成功（三音和弦）、无效操作（低鸣）、烧焦警告（双音警报）、金币（高音 ping）。
- BGM：8 秒轻柔五声音阶循环（正弦 + 缓慢包络），音量 0.2。
- 需在 Cargo.toml 启用 `bevy/wav` 特性（默认只带 vorbis/ogg）。

## 11. 数值平衡调整点

- 起始金币 60、房租 15 起步（+1/天）保持不变——前期宽松、后期有压力。
- 材料起手库存 6 份（4 种低阶材料），保证第 1 天不至于断料。
- 批量购买上限 10，提升中后期补货效率。
- 其余（配方价格、品质倍率、声望阈值、升级费用）维持已验证数值，本次不做大改，避免破坏平衡。

## 12. 工程约束

- 窗口版 `cargo run`；中文字体 NotoSansSC + ICU4X auto 特性保留；非活动面板 `Visibility::Hidden`；capture autopilot 按帧幂等；离屏 capture `IsDefaultUiCamera` + `WindowCamera(false)`。
- capture 模式自动关闭引导与暂停，保证 16s 证明视频确定性。
